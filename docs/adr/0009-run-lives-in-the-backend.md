# 跑链搬进后端，两个写者按「谁占着哪些文件」分权

ADR-0006 把执行图放开成可以分叉、可以成环，运行器就是走路；同一份 ADR 里留了一条待办：**跑链搬进后端**。理由当时就写明了 —— 定时触发（ADR-0005）和「网页不开也跑」都要求后端自己走图。这一单把它落了。

决定：

- 后端多一个运行器（`server/runner.mjs`）。跑之前先读一次 `mican.json`（前端在发起之前已经落过盘，ADR-0003，所以盘上那份就是最新的），然后它自己走路：`chain.mjs` 的 `routeFrom` 选路、`vars.mjs` 拼命令、`pick.mjs` 算提取节点的值，写缓存文件与下游文本节点的 md，再把结果元信息补进存档。前端只发 `POST /api/run`，拿一个 runId 去订事件流（NDJSON），最后一句 `end` 带着给人看的那句话 —— 说什么由后端拼，前端只负责显示。
- **停止落在后端**（`POST /api/run/:id/stop`）。前端那条订阅断了只是「不看了」，不代表不跑了 —— 所以停止不能再等于断 HTTP（以前那一下顺手把整棵进程树收掉）。走路的人在两步之间的空档里也要能被叫停，所以「停」是一笔标记，加上掐掉当前那条命令。
- **页面关掉链照跑**。这才是搬后端的意义；关页面、断电都不影响已经跑出来的结果（ADR-0005 预告过这件事）。网页再打开时 `POST /api/runs` 列出还在跑的，接上事件流：先把历史补上（含当前这一步已经攒下的输出正文），再跟着看后面。
- **跑链期间前端照样能改画布。** 两个写者写同一份工作文件夹，规则是：运行器占着的那些文件 —— 这一步正在跑的节点（它的缓存文件）、它要写的下游文本节点（它们的 md）—— 前端的整包落盘跳过它们。名单是「此刻」的，逐项现问，不提前算。其余文件照常写。

## Considered Options

- **跑链期间前端只读**：实现最省（不用分权），但 agent 节点动辄跑两小时，那两个小时画布动不了。否掉。
- **保持现状**（前端自己走图、后端只跑单条命令）：页面关着就断，ADR-0005 的定时触发也无处落脚。
- **后端整包写存档**：会和前端的整包落盘互相盖 —— 谁后写谁赢，一次覆盖就能把对方的改动抹掉。现在后端只补自己那两个键（结果元信息、下游正文）：现读现改。
- **事件流每次都带完整输出快照**：1MB 的输出反复搬来搬去。现在只带增量，重连时补一次当前这一步的正文。
- **跑完让前端重新拉一份画布**：会把用户跑链期间改的东西抹掉，等于偷偷回到「只读」。

## Consequences

1. `POST /api/exec` 没了。前端不再自己 spawn，`server/exec.mjs` 成了唯一一条起命令的路：命令行怎么起、输出怎么解码（UTF-8 优先、GBK 兜底）、超时、输出上限、连整棵进程树一起收，都在那一个文件里。
2. **存档仍由前端整包写**，所以它推过去的结果元信息可能有一瞬间落后于后端刚补上的那一份。收到 `done` 之后前端会再排一次落盘，几百毫秒内追平；页面关着时没有前端在写，后端的补写就是最终值。这条是靠「两边的值本来就一样」而不是靠加锁来的 —— 单机自用，够了。
3. **运行器的名单只活在内存里**。后端重启（`npm run dev` 重编译、断电）之后，跑了一半的链不会自己接着走：写下去的东西都在盘上，但「跑到哪了」没人知道。断在这里可以接受：重新点一次就是。
4. 「同一个节点不能同时跑两次」从「前端记着」变成「后端认名单」：第二次发起会被拒（"这个命令还在跑，等它结束"）。不同节点仍然可以并行 —— 这一条与搬之前的行为一致。
5. 跑完的记录在后端留两分钟再扔，给刚刚断线重连的页面补上最后那句话。
