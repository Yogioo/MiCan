# 空白处左键拖出来的是框选

Status: accepted · 已实现

一次只能选中一个节点，删一批要一个一个来。这一单做多选：在空白处按下左键拖出一个框，框住的节点与边一起选中，Delete 一次删掉；选中之后拖其中一个，整批一起走。

决定：

- **空白处的左键拖动改成了框选，不再平移**。一只手在空白处按下时想要的是「圈东西」；平移还有中键与空格 + 拖动两条路，框选没有别的地方可放。
- **节点与边都框**，判定的口径都是「搭上一点就算」，不是「整个装进框才算」——跟节点本身是同一个口径。节点比矩形（`rectsOverlap`）；边比它画出来的那根三次曲线（`curveHitsBox`）：端点被罩住最常见，先看一眼直接出结果；否则把曲线切成小段，一段一段比框。段与框的相交用 Liang–Barsky 裁 —— 只比取样点会从两点之间漏过去，一条长边在框里穿一小段就选不中了。取样数按曲线长度定（控制多边形长 / 6 世界单位，封在 16～160 段）。曲线从 `edgeCurve` 拿 —— 画线和命中算的是同一根线，不各算各的。这样框住一根线穿过的中间一段就能删掉它，不用把两头的节点也框进来。
- **选中是一个 id 集合**（`state.selection`，空集合就是没选）。节点 id 以 `n` 开头、边 id 以 `e` 开头，两类混在一处也认得出来：删的时候是边就 `removeEdge`，是节点就 `removeNode`。点一条边仍只选中那一条，只是表示成了只有一个元素的集合。
- **框选以框为准，不往上加**：按下的那一刻空白处先清空上一次的选中，之后框里有什么就选什么。想留一个外面没被框住的，就把它框进去 —— 这一版不做 Shift 追加。
- **选中不进存档，也不进撤销栈**。它是界面上的临时状态，跟视口一样不属于图结构；`update` 只在图结构变了时才推撤销（快照只取 nodes 与 edges），选中本来就落不进去。
- **多选之后拖动是「整批搬家」**：按在选中集合里的某个节点上拖，整批按同一个位移走。起点在按下时一次记全（`origins`），此后一次 `update` 挪完整批 —— 撤销也是一步，不是每个节点一步。点一下没拖动则收拢成只选它；改大小（`.node-handle`）仍只动那一个节点。边挂在节点上，跟着走，不必单独处理。
- **整批拖动压过划字**：会跑的节点正文允许划字复制，但从正文上按下时，单选是划字、多选是搬家 —— 选中了不止一个就以拖动为准，不然圈完一批却发现拖不动。

## Considered Options

- **空白处左键拖动仍平移，框选挂到 Shift 或右键上**：改动最小，但框选取代不了任何手势的位置，`Shift` 又与浏览器选中文本的惯性撞车，右键已经是节点菜单。
- **框选只框节点，边靠节点连坐**：命中判定最省（只要矩形），但「删掉画布中间那几根线」就只能一根一根点，框选最想解的就是这一类批量动作。
- **边用「两头都在框里」当命中**：不用碰曲线，但框住一根长线的中间一段却选不中它，跟节点的口径也不一致。
- **选中保持单个 `{ kind, id }`，框选只选最后一个**：那就不叫框选了。
- **空白处左键拖 = 平移，按住 Alt 才框选**：把最常用的那个动作藏在修饰键后面，与「框选要好用」的目的相反。

## Consequences

1. 平移少了一条最顺手的手势。中键拖动、空格 + 拖动都还在，滚轮缩放不变。
2. `state.selection` 从 `{ kind, id } | null` 变成 `Set`：读的地方都从 `state.selection?.id === x` 变成 `state.selection.has(x)`（节点、边两处渲染，加主装配层）。
3. `deleteSelection` 一次遍历整个选中：边自删、节点连坐（删节点时它的边跟着没）。Delete 与 Backspace 的行为不变，只是现在删的是一批。
4. 框选时每动一下指针就重算一次选中（走 `update` → 重绘），与平移时每动一下重设视口是同一个口径；框本身画在屏幕坐标里，挪一个固定定位的 div 就行，不跟着 `#world` 的变换走。
5. 多选整体拖动只认节点：位移按屏幕像素算、再除 `scale`，与单节点拖动同一个口径；起点在按下时固定，拖动中途选中集合变了也不影响这一趟。以后再做「选中范围改口径」时，命中判定已经在 `rectsOverlap` / `curveHitsBox` 上，选中也已经是集合 —— 不必再改表示。
