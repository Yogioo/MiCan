# 设置分两层：跟机器走的和跟画布走的

设置窗口里开始收各类配置（命令怎么跑、启动打开哪个文件夹、界面手感、跑链路最多几步）后，冒出一个绕不开的问题：这些值存在哪儿。只有两个候选：全部进画布存档，或者全部跟机器走。

决定：按一条判据分两层 —— **「换个工作文件夹打开，这个值该不该跟着变？」** 该变的进存档（**存档配置**），不变的跟机器走、存 `~/.mican/settings.json`（**全局配置**）。属于存档配置的是这份流程自己的东西：**运行目录**（命令在哪儿跑）和**跑链路最多走多少步**（护栏）。其余是全局配置。

判据的来路是 ADR-0001 / ADR-0003 已经立下的分界：存档要能拿到别的机器上打开，所以本机路径这类东西得想清楚再放。

补记：**运行目录最早放在全局那一层，实际用起来是错的** —— 你打开哪个工作文件夹，命令多半就在那附近跑，全局一份意味着每换一个工作文件夹都要去设置里重改一次。它挪进了存档（`FORMAT_VERSION` 5 的 `settings.cwd`）。原来那条「本机路径不进存档」的顾虑也站不住：节点自己的运行目录早就在存档里了，两层用同一套写法（相对工作文件夹或绝对路径）。

## Considered Options

- **全进存档**：换台机器打开就丢设置，而且界面手感、命令行这些东西与"这份画布"根本无关，会跟着存档到处漂。
- **全跟机器走**：一个流程想多转几圈，就得改整台机器的设置，会连累别的画布。
- **给每一项都做一次"存哪儿"的选择**：太碎。分两层 + 一条判据够用。

## Consequences

1. **`FORMAT_VERSION` 4 → 5**：存档顶层多一段 `settings`。旧版本（没有这一段）读进来按默认值走，不用迁移代码。
2. **后端只认自己用的那几个键**（`shell` / `timeout` / `outputLimitKb` / `recentMax` / `openWorkspace`），界面上那堆手感值它不认识，**原样存着走**。代价是后端不校验它们，所以校验前置在 `core/settings.mjs` 的表里（每项带 min/max，读数一律夹住、坏值退回默认）。运行目录不在这一层：它在存档里，跑的时候由前端连着节点那一层拼好、当 `cwd` 发过去。
3. **手感值集中在 `core/settings.mjs` 一张表里，用的时候现读**（`machine.zoomMax`、`canvas.stepLimit`），不往纯函数签名里传参 —— 缩放、点阵、几何这些函数被调得太频繁了。所以设置窗口改完立刻生效，不需要重开页面。
4. **撤销快照里没有 `settings`**：`deserialize` 只把它原样带出来，由打开工作文件夹那条路收进去。否则每一次撤销都会把画布配置抹回默认。
5. **「启动时打开的工作文件夹」在「打开」弹窗里勾选**（你开哪个文件夹的时候才想得起来这件事），设置窗口不画它 —— 表里标 `tier: 'hidden'`。提交时也不带它，否则一个空串会把存在那儿的路径冲掉。同一个理由：设置窗口里「细节」收起来的那 12 项照旧提交（它们本来就是画出来的）。
