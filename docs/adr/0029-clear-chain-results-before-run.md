# 跑链前清空链身里的旧输出

Status: accepted · 已实现

会跑的节点把最近一次的输出一直摆在身上（[ADR-0002](./0002-memory-is-source-of-truth-save-writes-disk.md) 那套缓存文件）。
一条链有多条分支时，这会骗人：这一趟走的是这条分支，没走到的那个节点还挂着上一趟的输出，
看上去却像是「这趟跑出来的」。运行历史（`runs.jsonl`、`.mican/runs/`）记着每一次，但节点上摆的只有最近一次。

问题不在「留着上次的结果」，而在**一条链的一次运行没有把这条链的痕迹摆干净**。人看节点判断
「这趟走到哪、各步出了什么」，靠的就是这排节点上的输出。

## 决定

- **从触发节点（入口 / 定时器）跑链之前，先把链身里那些会跑的节点的上一次结果清掉**。链身就是
  [ADR-0027](./0027-busy-chain-blocks-a-trigger.md) 那个 `reachable(graph, head)` —— 这一趟可能走到的
  命令、提取、写入节点全算，包括不会走到的分叉。
- **清的是结果，不是图**。内存里的 `result` 置空；磁盘上那份节点的缓存文件（`.out`）、诊断（`.log`）、
  出口边车（`<id>.<出口>.out`）删掉；`.mican/results.json` 里那几格忘掉。节点本身的位置、命令、
  端口、正文一概不动。
- **不动运行历史**。`runs.jsonl` 和 `.mican/runs/` 是「谁在哪一刻跑了什么」的记录 ——
  要看清运行流程靠它（将来那条给人类看的事件日志也长在它上面），清掉就把唯一的凭证弄没了。
- **不动下游文本节点的正文**。那是用户/上游写进去的东西（可能本身就是手写的稿子），
  按节点 id 一眼分得清「缓存」和「文档」，不混着清。
- **只在从触发节点跑链时清**，手点单个会跑的节点的「运行命令」不清：那一次跑的本来就是这一个节点，
  节点上摆着它自己的上次输出是它的上下文，不是错觉。
- **默认开着，做成一条跟画布走的设置**（「运行」组，键 `clearOnRun`，默认 `true`）：这是这份流程
  自己的运行习惯，换工作文件夹就换一套，和 `stepLimit`、`cwd` 同族。不想每次清的人可以关掉。
- **清完告诉前端一声**。事件流里多一句 `{t:'clear', ids}`，前端把那些节点的 `result` 收干净。
  清空不是图上的改动（不进撤销栈）；后端的落盘保护照旧 —— 这一趟跑到的节点由运行器写。
- **后端是清盘的那一头**：页面关着、定时器到点自己跑的那些趟，盘上也得是干净的。

## Considered Options

- **只在界面上把节点抹空，盘上不动**：刷新一下旧输出又回来；页面没开时更是白清。
- **清整条链的图，重建节点**：把位置、命令、端口一起动了，代价和风险都跟「清输出」这件事无关。
- **连下游文本节点的 md 一起清**：写进去的正文既是这趟的产物，也是用户可能在改的文档；
  一份文件两种身份时不能一把删掉——要清也得先分清是谁写的，留到真被咬到再说。
- **连运行历史一起清**：「避免错觉」的代价变成「查不到发生过什么」，正好和运行历史的本意相反。
- **摆一个「上次」的标记，而不是清掉**：节点上再多一层状态、界面再多一套说法；要的其实是干净。
- **默认关着，想清的人自己开**：那痛点原样留着，大多数人不改默认值。
- **跟机器走的设置**：这是这份流程的行为（同一条链换个人看也一样），不是这台机器的手感。
- **手点「运行命令」也清**：它只跑一个节点，不构成「一趟链」，清掉反而抹掉了要对照的上一次。
- **清那些节点已经写出去的下游正文**：同「连 md 一起清」。

## Consequences

1. `src/core/settings.mjs` 多一条 canvas 字段 `clearOnRun`（新 kind `bool`），
   `src/ui/settings-dialog.mjs` 的 `fieldRow` 多一个复选框分支。存档格式不升版
   （缺键就是默认，和 ADR-0027 的 `onBusy` 同一种做法）。
2. `server/runner.mjs` 在 `start` 里多一步：`mode === 'chain' && canvas.clearOnRun` 时删掉链身那些节点的
   缓存三件套、`archive.mjs` 多一个 `forgetResults(root, ids)`。`clearResults` 按 id 开头认名字，
   `runs.jsonl` / `runs/` / 别的节点的文件都沾不上。
3. 事件流多一种 `clear`；`src/ui/main.mjs` 的 `applyRunEvent` 跟着把节点抹空。
4. 清空发生在点火那一刻、第一步之前：链身被占而没跑起来的那一下**不会**清（判据在那之前，
   且它根本不是一趟运行）。
5. 关掉这条设置就回到今天的行为：节点上一直摆着最近一次的输出。
6. `CONTEXT.md` 不加新词：「缓存文件」那条本来就是「最近一次运行留下的输出」，这一单只是让
   跑链时它先空一次。
