# 扩展的出口写在清单里

Status: accepted · 已实现

扩展吐 JSON，链上却只能整份往下送，或另接提取节点（ADR-0007）取一个字段。需要的是和 `args` / `defaults` 对称的一份**声明**：这份扩展有哪些出口、选路看哪一个。

决定：`EXTENSION.md` 加缩进的 `outputs:`（名字 → 取法）和可选的 `route:`（哪个出口当执行边的选路值）。扫描仍只读 yaml 头。数据边加可选的 **出口名**（存成 `fromPort`）；空着仍送整份值，旧存档不用涨 `FORMAT_VERSION`。

不从某次运行的 JSON 键自动长端口。true/false 不做成节点上的执行出脚 —— 分路仍在执行边上（ADR-0006）。提取节点留下，手写命令和临时取字段还靠它。对象/数组不当值、不序列化成一团；多行字段可以走 `[[ ]]`，边车文件挨着缓存文件，节点的值仍是整份 stdout。

## Considered Options

- **按这次 stdout 的键长端口**：跑一次一个样，菜单与连线跟着飘，和「声明是静态清单」（ADR-0013）对着干。
- **true/false 做成执行出脚**：分路搬进节点，和 ADR-0006 对着干。
- **FORMAT_VERSION 7**：没有出口名就是整份值，不必涨版本。

## Consequences

1. 改 `outputs` / `route`，所有引用立刻跟着变（跟 ADR-0014 同一条路）。
2. `route` 省略时选路仍比 `stdout.trim()`，旧扩展不用改。
3. 声明了却取不到（缺键、不是 JSON、不是一个值）停并报错，不静默给空。
