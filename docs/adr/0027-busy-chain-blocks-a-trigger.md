# 链身被占就不点火

Status: accepted · 已实现

[ADR-0010](./0010-trigger-nodes-entry-and-timer.md) 定的判据是「有没有一条从**同一个起步节点**出发的链还在走」。它兜得住同一条链重入 —— 人手从入口点一下、定时器到点，按起步的会跑节点算身份，本来就是同一条链，不该同时跑两遍 —— 但兜不住「相连的节点正在跑」。这一单把判据从「起步节点」换成「链身」。

先把话摆正：今天没有任何一处会掐别人的进程（`stopAll` 只有进化在调）。撞上的后果是**两个进程同改一份工作文件夹**：同一个节点的缓存文件、同一个下游文本节点被后跑的那条盖掉，先跑的那条结果在盘上没了。表现是「互相盖」，不是「被强停」。

## 两个缺口

1. **起点不同、下游撞车**。`入口A → A → B → pi`，另有 `定时器T → B`。链 A 停在 A 这一步，T 到点：B 还没进过任何一条链的名单，判据看不见，照跑；等链 A 走到 B，两条链在 B 上并发 —— 同一个 pi 节点两份活。
2. **手点的「运行命令」不在判据里**。链停在 A，手点 pi 的「运行命令」不碰判据，放行；链走到 pi 时也没人拦。

## 决定

- **判据是链身**：从起步的会跑节点出发、顺执行边能走到的那些会跑的节点。三种会跑的节点（命令、提取、写入）全算 —— 提取和写入虽快，一样写缓存文件、一样写下游文本节点。分叉两边都进链身：哪条执行边会被走到，要跑完那一步才知道。手点的「运行命令」不是链，它的链身就是它自己。
- **只在一个地方查**：发起时（`runner.start`）算出这次的链身，跟在跑的那几条比，有交集就不点火。查与登记之间没有 await，所以两枚入口同时点也必然后来那枚看得见先来的那枚。链走起来之后不用再查：一条链只在自己的快照图上走，「以后会碰到的节点」必然是发起那一刻那份链身的子集 —— 撞车只可能发生在点火这一刻。
- **让路由发起方定，谁也不会被抢占**：触发节点看自己的开关（「在跑就跳过」/「照跑」），手点的「运行命令」永远让路。「照跑」的意思是「我这条链不让路」，不是「别人得给我腾地方」—— 已经跑起来的链不会被谁停下。
- **手点的「运行命令」一并管**：链在跑时，链身里的节点不给手点。不管就是只挡了一半的门：链正往 pi 走，人先手点一下，一样是两份活同改一份文件。
- **开关在两枚触发节点上各一份**：入口 body 里那行字下面、定时器的控件栏里各加一行两选一（复用定时器模式按钮那套样式）。默认「在跑就跳过」——定时器这头跟今天一样（今天就是跳过这一圈），入口这头是一次行为反转（今天只在撞上同一条链时才拒）。
- **被占看得见**：触发节点的脚上分两种状态 —— 自己那条链从这儿在走是「运行中」（今天的样子），别的链占着它的链身是「让路 · <起步节点名> 在跑」，配一个跟 `.running` 同族但不同色的样式，一眼分得清「能点」和「点了没用」。`/api/runs` 每条多带一个 `headId`，前端拿它在内存的图上算链身（跟后端共用 `reachable`）。
- **被拦下来只有一句提示**，说的是谁占着（「点不了：从 <节点名> 起步的链还在跑，它会走到这个节点」）。入口不落盘 —— 人手点的，人当场看见了；定时器那一笔照旧写进 `results[定时器 id]`（`skipped: true`）。工具条那个「开始」一次点好几枚入口，几条消息合并成一句报，不然只看得见最后一条（`showMessage` 是覆盖 + 五秒消失）。
- **存档多一个字段**：`onBusy`，值 `skip` / `run`，缺就是 `skip`，7 版不升。旧存档打开时按默认显示成「在跑就跳过」—— 就地掰正，跟 ADR-0010 第 8 条同一种做法。
- **判据只看会跑的节点**：两条链共享一枚文本节点（一条写、一条读）也互相干扰，那是更宽的一圈，这单不开。

## Considered Options

- **保持「同起步节点」**：上面两个缺口都漏。
- **只按「此刻已经占着的节点」比**：兜住手点那半，漏「还没走到」的将来撞车。
- **把「会写的文本节点」也算进链身**：两条链只要指向同一份 md 就互相挡，挡得莫名其妙。
- **只挡触发节点、不管手点的「运行命令」**：开关只挡一半的门。
- **每步起跑前再查一次**（初稿的写法）：查的是一个不可能出现的状态 —— 跑链期间改画布改的是盘上那份图，在跑的链不跟着改，它走不出自己的链身。而它带来的 `blocked` 是第三种收尾语义（不是失败、不是停止），要在界面上和文档里各解释一遍。
- **拦下来排队，而不是跳过**：ADR-0010 已经否过一次（agent 节点会越堆越多）；手点的那次由人自己再点一下就行。
- **三态（跳过 / 排队 / 照跑）**：多一个几乎没人用的状态。跳过与照跑已经把「要稳妥」和「要灵活」两头给完了。
- **开关做成存档配置一条或全局配置一条**：入口是人手点的（想照跑往往是真的想现在跑），定时器是到点自己跑（没人看着，跳过更安全），两枚触发节点的诉求本来就不一样；一刀切还会让「这条链我就想让它照跑」没处表达。
- **被占只在点了以后才说**（初稿的写法）：判据放宽后「点不动」会变成常事却毫无预告；判断的原料前端本来就有。
- **跟「运行中」用同一个标记**：把「这条链在跑」和「这条链被占着」混成一件事，而它们的区别正好是「点了有没有用」。
- **ADR-0004 第 2 条「要同时做两件事，就画两条链、各自有入口」**：没被推翻，只是给那两条链加了个「别撞链身」的前提。

## Consequences

1. `runner.isRunning(headId)` 换成「链身有交集」；`src/core/graph.mjs` 多一个 `reachable(graph, id)`（顺执行边算闭包，带 visited 防环），前后端共用。`server/scheduler.mjs` 与 `server/api.mjs` 的接线不变，只是这一层不再收「一个起步节点的 id」。
2. 判据放宽的代价：一份画布上只要有一条链在走，任何和它共享一个下游节点的入口都点不动。单机自用、agent 动辄跑几十分钟的场景下这是要的那一头；代价是界面上必须说清「为什么点不动」—— 「让路」状态与那句提示就是它的兑现。
3. `src/core/serialize.mjs` 里 `entry` / `timer` 各多一行 `onBusy`；`src/ui/nodes.mjs` 里入口的 body 现在是 `flex` 居中一行灰字，要改成竖排才放得下那行控件。`/api/runs` 的每条与事件流里那句 `run` 都多一个 `headId`。
4. `CONTEXT.md`：新词「占用」，「入口节点」「定时器节点」两条里「一条链还在跑时，这一圈跳过」改成按开关说 + 链身被占也算。
5. ADR-0009 第 4 条（「不同节点仍然可以并行」）与 ADR-0010 的判据被本单收窄，各加一句 Status 注记；ADR-0004 第 2 条不动。
6. 进化的那条路不动：自动进化本来就是等所有链跑完再进化（[ADR-0024](./0024-evolve-panel.md)）；手动进化与撤销/还原是显式动作，照旧先停链。
7. 剩下的窄口子：两条链都还没走到、但盘上共享同一份文档那一类 —— 判据只算会跑的节点，看不见它，留到真被咬到再说。
