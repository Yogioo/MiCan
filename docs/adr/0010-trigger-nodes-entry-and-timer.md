# 入口与定时器是独立的触发节点

Status: accepted · 已实现

[ADR-0006](./0006-exec-graph-branches-and-loops.md) 收尾时留了两件事：定时触发（[ADR-0005](./0005-scheduled-runs-live-in-the-backend.md)）与入口的形态。这一单一起落了。

决定：

- **「入口」从命令节点上的一个布尔值，变成一枚独立节点**（`kind: 'entry'`）。它只有一根执行出边，指向链的第一个会跑的节点；没有值、没有缓存文件、没有数据端口。这样「从哪儿开始」是画布上看得见的一枚节点，而不是某个命令节点身上一个不显眼的标记；将来做子图，子图的入口就是它 —— 一个子图有明确的入口节点与（以后的）出口节点，就能被别处整个调用。
- **「定时器」是第二枚触发节点**（`kind: 'timer'`）。它上面写一行时间表，一根执行出边指向一个入口节点；到点由后端的调度器从那个入口出发跑完整条链。定时器不直接连会跑的节点，免得「一条链两个起点」说不清。
- **两枚触发节点合称「触发节点」**：会跑的节点的反面 —— 只有执行出边，没有值、没有缓存文件、也不传数据。
- **时间表在节点上就是控件**：一排按钮切模式（固定间隔 / 每天），间隔填数值加单位（秒 / 分钟 / 小时），每天填时刻；改完即生效。存下来的仍是一行文本（`每 30 秒` / `每 30 分钟` / `每天 09:30`），解析在 `src/core/schedule.mjs`。这一行文本是唯一的真相：界面只往它上面写，调度只从它上面读，导入一份手写的存档跟界面上点几下落到同一个地方。控件不自己保留第二份状态（哪个模式的值在存档里就显哪个），所以「存档里写的是什么」与「界面上显示的」不会分叉。认不出来的文本（只有手改存档会遇到）标红而不静默当成没设。
- **间隔型对齐到固定相位**（每 30 分钟就是整点与半点）。这条不是洁癖：前端每次落盘、后端就重装一次时刻表，如果间隔从「此刻」起算，倒计时会被一次次推后，结果永远不响。
- **到点时上一条还在跑就跳过这一次**，并把这个「跳过」记在定时器节点上。判据是「有没有一条从同一个入口出发的链还在走」—— 只看它自己那条链，别的链（人点的、别的定时器的）照常。
- **旧的 `entry: true` 标记不保留**：存档版本升到 6，5 版及以前载入时把旧标记就地换成一枚入口节点加一根执行边，画布照样跑，不用用户重连。

## Considered Options

- **定时挂在命令节点当入口时的一个属性上**：改动最小，不用新节点种类。但「入口」从此有两种表达，子图那一步也要再迁一次；不如现在一次做对。
- **定时器直接连会跑的节点**：少一层入口。但那样「一条链」的起点就有两个来源，运行器与「还在跑就跳过」都得分情况判断。
- **保留 `entry: true` 与入口节点并存**：兼容最省，但两套语义会一直同时活着。
- **间隔从「装载时刻」起算**：更符合直觉，但会被每次落盘的重装推后（见上）。
- **排队或并发**：跑到点时的另一条选择。并发会让两个进程同时写同一批缓存文件与下游 md；排队会让 agent 节点越堆越多。跳过是最不会把事情搞坏的那个，代价只是「这一圈不跑」。

## Consequences

1. `setNodeEntry` / `entry` 字段没了，判断「链的起点」一律看节点种类。
2. 执行边的规则按源节点分：`timer → entry`、`entry → 会跑的节点`、`会跑的节点 → 会跑的节点`。违反的组合在建边时就被挡下，存档里遇到也直接丢掉。
3. 跑链从「入口」出发，第一步永远是入口那根出边指到的节点（入口自己没有进程）。`POST /api/run` 的 `mode: 'chain'` 现在要求 `id` 是一枚入口节点。
4. 后端的调度器（`server/scheduler.mjs`）持有的只是内存里的定时器表；时刻表的真身跟着画布走在 `mican.json` 里。前端每次落盘、每次换工作文件夹之后，后端重装一次；没变的定时器原地不动（配合相位对齐，不推后）。
5. 定时触发的那一笔（跑了 / 跳过了 / 没跑起来）写进存档的 `results[定时器 id]`，跟运行结果走同一条路 —— 前端整包落盘时才带得回去。这跟运行结果的补写是同一个口径：后端现读现改，可能有一瞬间落后于前端那一整包（ADR-0009 的第二条顺带），前端下一次落盘就追平。
6. **页面开着时怎么知道**（ADR-0005 留的最后一问）：`/api/runs` 在「在跑的那些」之外多返回一份触发记录；前端每 3 秒问一次，没见过的 `runId` 接上事件流（`attach` 会重放历史，所以就算这一圈已经跑完也接得到），触发记录摊到定时器节点上。不新增长连接，也不整包重拉画布。
7. 新建的定时器节点直接带上默认时间表（`每 30 分钟`），所以在界面上点一下就有个能跑的定时器；存档里缺这一段或缺成空串时也按这个默认补。
