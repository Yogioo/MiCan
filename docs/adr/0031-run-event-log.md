# 运行事件日志：按天一份，值走附件引用

Status: accepted · 已实现

软件持久运行时，定时器会一遍遍点火（「长城任务」是秒级的），而人**看不到每一趟干了什么**：
节点上只留最近一次的输出（缓存文件每次覆盖），定时器脚上只有「上次 09:31（跳过）」，
`server/scheduler.mjs` 的触发记录只在内存里存 50 条。ADR-0020 已经有 `.mican/runs.jsonl`，
但它是**给机器看的**——缺的正好是人要的那几样：

| 缺口 | 现在 |
| --- | --- |
| 没有「一次运行」这个单位，只有「一步」 | 一行 = 一个节点跑完。整条链的结论（跑完 / 卡住 / 超步数 / 失败）只在内存事件流的 `end` 里，**落盘没有** |
| 链名是个 id | `chain: "n1"`。ADR-0030 的注释（人写的链名）在这之后才有，历史里认不出哪条链 |
| 「没跑」完全看不见 | 验不过 / 变量没对上 / 扩展读不到的那一步，`runner` 在 `remember()` 之前就 return 了；被链身占用而跳过的那一笔只在内存 + 定时器节点那一格 |
| 值没留 | ADR-0020 明说不留。而人看「为什么卡住」最需要的就是边上的值 |
| 详情会指空 | `runs/*.log` 每个节点只留 `runLogKeep`（默认 20）份，越老越是死链 |
| 秒级任务下会胀死 | ADR-0020 写明「只追加、不轮转」。一秒一次 × 一天，UI 端不可能整份读 |

诊断扩展（交给 pi 的那份 JSON）读的也是这份东西，所以它**同时是人和 AI 的唯一事实来源**：
两边的故事必须一样，否则会出现「诊断说这根边没走过、界面说走过」。

## 决定

### 一次运行 = 一段可折叠的记录

新日志记的是**运行**，不是孤立的步骤。一行一件事，`t` 区分：

```json
{"t":"run","runId":"r1abc","at":1730000000000,"mode":"chain","by":"timer","from":"n1","chain":"收单链","head":"n2","cleared":["n2","n3"]}
{"t":"step","runId":"r1abc","at":1730000000012,"node":"n2","name":"拉工单","step":1,"ms":1834,"code":0,"failed":false,"route":"有单","routeValue":"3 单","digest":"3 单待处理","wrote":[{"node":"n3","file":"docs/工单.md"}],"in":"…-n2.in.json","out":"…-n2.out","log":"…-n2.log"}
{"t":"skip","at":1730000000012,"mode":"chain","by":"timer","from":"n1","chain":"收单链","why":"busy","note":"让不开：从「收单链」起步的链还在跑，它的链身走到这儿"}
{"t":"end","runId":"r1abc","at":1730000000012,"outcome":"ok","steps":4,"ms":12400,"message":"链路跑完：4 步，走到一个没有出边的节点"}
```

- `run`：**开跑那一刻就写**（实时盯要靠它）。`by` 是 `manual` / `timer`；`mode` 是 `chain` / `node`；
  `from` 是点火的那枚触发节点，`chain` 是链名（注释优先，其次起步节点的 `name`，跟 ADR-0030 同一份口径），
  `cleared` 是跑链前清掉旧结果的那些节点（ADR-0029）。
- `step`：一步跑完写一行，**只有跑完才写**。`route` 是走的那根执行边的标签、`routeValue` 是选路用的那个值（截短）、
  `digest` 是输出的首行（截短），两者都只为列表好认；`wrote` 是这一步写进的下游文本节点。
- `skip`：**点火了但没跑**，自己一行（一票运行级事件）。`why` 是 `busy`（链身被占）/ `evolving`（正在进化）。
- `end`：`outcome` 是 `ok` / `failed` / `stuck` / `limit` / `stopped` / `error`，`message` 就是今天那句人话。
  没有 `end` 行的 `run` 就是「还在跑」。

**不记 chunk。** 一秒一次的链上，输出块是天文数字；正在跑的那一步在面板上显示「进行中」，
正文去节点上看（节点上本来就有 live 输出）。面板 = 日志（已完成的）+ `/api/runs`（在跑的），两样都不新造。

### 值走附件，jsonl 只记引用

**一个节点的一次运行 = 一组附件**，jsonl 行里只有相对路径和摘要：

```
.mican/log/<YYYY-MM-DD>.jsonl          上面那些行，按天一份
.mican/runs/<YYYY-MM-DD>/<at>-<node>.out       这一步的输出全文（= 它的值）
.mican/runs/<YYYY-MM-DD>/<at>-<node>.log       这一步的 stderr 全文（含动作行，ADR-0021）
.mican/runs/<YYYY-MM-DD>/<at>-<node>.in.json   这一步实际拿到的输入 + 替换后的命令
```

值一律进附件，不设「多大才另存」的门槛：口径只有一条，实现和解释都简单，信息一点不丢。
jsonl 行里那几个截短字段（`routeValue` / `digest`）只是**给列表看的索引**，不是值的住所 —— 全文永远在附件里。
输入快照就是 `vars` 那份东西（名字 → 值 / 路径 / 是否人填的）加上 `applyVars` 出来的实际命令；
选路用的值本来就是这一步自己的输出，附件里也有，`routeValue` 只为不用点开就能看。

`.in.json` 里那个名字的来源（入边的来路节点 / 常量 / 面板 / 扩展默认值）由 `collectVars` 的路径决定，
值本身取的是它当时真正写进命令的那一份——「这条链这一步吃了什么」从此可查。

### 过期清理

`logKeepDays`（机器设置，默认 7 天）是唯一的规模控制：按天的 jsonl 连带**同一天**的 `.mican/runs/<日期>/` 整目录删掉。
后端启动时扫一遍，之后每天一次。ADR-0020 那个 `runLogKeep`（每节点留 N 份）退休 ——
两条规则叠起来要理解两次，而按天已经封顶；秒级链下「每节点 20 份」只覆盖几分钟，等于没有。

附件被清掉而 jsonl 行还在（超过保留天数的行本来就一起删了，所以只可能出现在手动删附件的情况下）：
面板照实写「全文已清理」，不假装点得开。**日志行本身不因为附件被删而删**，时间流不留洞。

### 谁写

- `runner`：`run` 行在 `start` 里、`step` 行在 `settle` 之后（跟今天写 `runs.jsonl` 的位置一样）、`end` 行在 `finish` 里。
- `scheduler`：被拦下的那一下（`busy` / 正在进化）写一行 `skip` —— 「为什么今天这条链一次没动」只有它能回答。

进化 / 商量期间**照写**：`.mican/` 是缓存目录（ADR-0026），不在 pi 能改的三层里，也不进快照和 commit，
写它不违反「进化期间只读」（那条只读管的是不起新运行、拒收前端落盘）。

### `runs.jsonl` 退役

新日志接手它的角色，**不并存两份**：并存迟早会分叉出两套故事。

- `builtin/extensions/diagnose/run.mjs` 改读 `.mican/log/*.jsonl`：仍按节点聚合出今天的形状（pi 的提示词不用大改），
  但能按 `runId` 成组了 —— 多出「每条链的结局分布」和「连续 N 次都卡在同一根标签」。
- `server/evolve.mjs` 的 `triggerOf` 改读它；`runs` 条件从「多少个**步**」改成「多少次**运行**」（这才是那个词的意思），
  `streak` 仍按 `step` 行的 `failed` 连败算。
- 老工作文件夹里已有的 `runs.jsonl` 不再被读，也不迁移 —— 它是缓存目录里的东西，本来就能整个删。

### 面板

工具条上一个「运行日志」按钮，右边抽屉（复用 `src/ui/evolve-window.mjs` 那套壳）。**三层折叠，一层对一层：**

```
▸ 09:31:07  「收单链」· 定时器点火 · 跑完 4 步 · 12.4s · 写入 2 份
  ▸ 1 拉工单       out 3 单 · 1.8s · route「有单」
  ▾ 3 pi 改代码    in {{patch}}=docs/… · out review, summary · 4.2s · 退出 0
      [查看全文]  [聚焦这个节点]
  ✗ 4 提交         in {{msg}}=…   变量没对上：{{sha}} 没有来源
```

- 一折：一次运行一行，带结论、谁点的火、哪条链。
- 二折：展开见这次的步骤表（节点 · 入 · 出 · 耗时 · 走的哪根边 · 退出码）。
- 三折：再展开一步＝那份 stdout / stderr 全文（动作行照 ADR-0021 藏掉）。
- **连续成功压缩**：同一链连续 ≥ 20 次 `ok` 折成「09:31–10:59 · 收单链 · 连续 1 790 次跑完 · 无异常」一段，可展开。
  **异常和跳过永不折叠。** 秒级任务跑一天，时间流仍然读得动。
- **跟随 / 暂停**：默认贴底跟着新行；人往上滚就自动暂停（不被新行顶走）。这是「旧输出被覆盖」的正解。
- 过滤：全部 / 按链 / 只看异常；日期往回翻读更早的那几份。
- 点一行：画布移过去并选中那个节点（复用选中和视图那两套现成的）。
- 入口两处，共用一个窗口：工具条那个是全局流；触发节点脚上「上次 09:31」那格点开是**带这条链过滤**的同一个面板
  （画布缩小时节点不好找，但从图上直接看这条链要有路）。

接口：`/api/log`（读某天 / 某个 `runId` / 某个链）+ 增量轮询（`after=<序号>`），复用 `pollRuns` 那套 1 秒 / 3 秒的节奏。
**不再加一条 SSE**：时间流跨运行、跨刷新、跨重开，轮询增量比 SSE 补历史简单。

## Considered Options

- **往 `runs.jsonl` 里加运行级的行**：诊断把每一行都当一步、按 `node` 分组，没有 `node` 的行会变成幽灵节点；而且 chunk、输入输出都要另外长字段，越改越像新文件。
- **值内联进 jsonl**：一秒一次的链一天八万次，每次几百字节就是 GB 级；变大之后「只读末尾几百行」也变慢。
- **内联 + 超上限截断**：会丢信息，而「值就是这条链怎么走的」本身。
- **附件照 ADR-0020 每节点留 N 份**：秒级链下只覆盖几分钟，等于翻历史全是死链。
- **另开一份「给人看」的日志、机器那份照旧**：人和 AI 会看到两套故事。
- **实时输出（chunk）也进日志**：行数是天文数字，而节点上本来就有 live 显示。
- **面板另加一条 SSE 流**：跨运行、跨刷新要自己补历史，比轮询增量复杂。

## Consequences

1. `src/core/paths.mjs`：加 `LOG_DIR`、按天的文件名、`runs/<日期>/` 那套；`RUNS_FILE` 退役。
2. `server/runner.mjs`：`remember` 改成写新日志 + 三份附件；`run` 行挪到 `start`、`end` 行挪到 `finish`；
   ADR-0029 清掉的那些节点进 `run` 行的 `cleared`；`keepLog` 的每节点裁剪删掉。
3. `server/scheduler.mjs`：`busy` / 正在进化那两笔各写一行 `skip`（含「进化期间」那种）。
4. 设置项 `runLogKeep` 换成 `logKeepDays`（默认 7 天）：`src/core/settings.mjs` 那一项和 `server/api.mjs` 里 `clampInt` 那一行跟着改；
   后端启动时按天清一次，之后每天一次。
5. `builtin/extensions/diagnose/run.mjs`：按运行读新文件，输出多几项（每条链的结局、卡住的标签）。
6. `server/evolve.mjs:217` 的 `triggerOf` 改读新文件，`runs` 条件改成数运行。
7. 新增面板与 `/api/log`；工具条一个按钮，触发节点脚上那格可点（带链过滤）。
8. 已知风险：单日巨量（一天几十万个附件文件）。现成的缓解是 stdout / stderr 为空就不落文件；
   真被打爆再加单日上限，现在不做。
9. `.mican/` 整个可以删（ADR-0026）：删掉就是日志和详情都没了，画布和文本节点不受影响。
10. 老工作文件夹里的 `runs.jsonl` 不再被读也不迁 —— 面板上看不到迁移前的历史。
