# 诊断：分出「上次改动之后」

Status: accepted · 已实现

[ai-evolution.md](../ai-evolution.md)「三个会翻车的地方」第一条：不做改前改后的指标对比，全靠后续纠偏；
但诊断眼下把全部历史混在一起算，某次进化把链改坏了，连败要攒很久才压过之前的好成绩，pi 也不知道该先看自己上次改的东西。

决定：

- **「改动」指最近一次落下了 commit 的进化或撤销**：从 `.mican/evolve/history.jsonl`（ADR-0024）里取最近一条带 `commit` 的记录，
  它的 `at` 是分界。没有记录就不分，输出照旧。用户在画布上的手改不算：它们不 commit，时刻也不可靠。
- **诊断输出多一个 `change`**：`{"at":…,"commit":"e4f5a6b","by":"streak"}`。
- **每个节点多一个 `since`**：分界之后的 `runs` / `failed` / `stuck` / `avgActs`，算法跟全量那份一样。
- **标出「改动之后才开始」**：分界之后至少跑了 3 次，且失败或停住的占比比分界之前高出一半以上（之前是 0 就看之后是否过半），
  这个节点带 `worse: true`。分界之前没跑过的节点（新加的）不标。
- `text` 里被标的节点单起一行：`n7 在 e4f5a6b 之后败 4/5（之前 1/20）`，排在最前。
- 进化的提示词里，有被标的节点就加一句：「这些节点是上次改动之后才变差的，先看上次改的是不是原因，是就改回来」。

## Considered Options

- **分界取 git 里三层最近一次 commit 的时刻**：进化前的快照也是 commit，会把分界推到进化开始那一刻，意思一样但多绕一层；
  用户自己的 commit 也会算进来。先只认进化记录。
- **每一行运行历史记上当时存档的 commit**：分得最准，但要改 ADR-0020 的格式，运行器每跑一步还得问一次 git。先用时刻分。
- **统计检验判断「显著变差」**：运行次数少时检验没意义，反而难懂。用固定的门槛。

## Consequences

1. 依赖 ADR-0024 的进化记录；没有记录的工作文件夹诊断跟现在一样。
2. 门槛是写死的，少量运行时会误报或漏报；误报的代价是 pi 多看一眼上次的改动。
3. 诊断仍然只读，不自己回滚：改不改回来是 pi 的判断，最后兜底的是面板上的撤销。
