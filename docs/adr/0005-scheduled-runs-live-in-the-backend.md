# 定时触发由后端调度，不用前端定时器

Status: accepted · 调度本身未实现（跑链那一半已由 [ADR-0009](./0009-run-lives-in-the-backend.md) 落地）

命令节点的定时触发（到点自动跑一条链）只有放在后端的 Node 中间件里才成立：定时的意义就是「不用人在场」，而前端定时器要求页面一直开着 —— 那不是自动化，只是「你恰好开着页面时顺便跑一下」。

决定：后端持有时刻表与入口列表，到点自己沿执行边把整条链跑完。代价是后端要懂画布（读 `mican.json`、顺着执行边走路、按数据边的变量规则拼命令），而它现在只知道工作文件夹。好在 `graph` / `chain` / `vars` / `paths` 都是纯 ESM，前后端可以直接共用，`paths.mjs` 已经开了这个头。

## Considered Options

- **前端定时器**：页面关着就停，等于没解决「不用人在场」这件事。
- **Service Worker / 浏览器保活**：还是要页面在场，而且多一层生命周期要管。

## Consequences

ADR-0003 之后这件事变简单了：后端跑完直接把缓存文件与存档写掉，不需要「结果先攒着、下次打开页面时取回」。关页面、断电都不影响已经跑出来的结果。

实现前还要定的语义（都属于定时本身的题，不在双流模型那一单里）：

- 时间表用固定间隔，还是「每天几点」这类表达式
- 到点时上一条还没跑完：跳过、排队，还是并发
- 多个入口同一时刻到点
- 页面此刻开着的话，界面怎么知道链已经在后端跑过了
