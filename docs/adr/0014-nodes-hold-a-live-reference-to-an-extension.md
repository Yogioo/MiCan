# 节点是对扩展的活引用

Status: accepted

决定：由扩展生成的节点**只存扩展目录的相对路径**（如 `nodes/git-status`），不存命令文本。命令在每次运行时现拼：

```
node "<工作文件夹绝对路径>/<扩展目录>/<entry>" <args>
```

- `entry` 与 `args` 来自 [ADR-0013](./0013-extension-declaration-is-a-static-manifest.md) 那份清单，静态读文件就有，不需要执行任何用户代码。
- `{{名字}}` 仍然只从**数据入边的标签**取值 —— `collectVars()` 报缺边，「固定输入」这件事**零新增机制**。
- **工作目录是节点的**（沿用现有的「节点 > 画布 > 工作文件夹」），扩展目录只用来定位脚本文件。因为「在哪儿跑」本来就是这类动作的参数：把 `git status` 封装成扩展，参数就是运行目录，而不是让调用方再多传一个 `--workspace`。

**不新增节点种类**：它就是一个命令节点，只是命令文本的来源从「用户手写」换成了「按扩展拼」（存档里凭有没有 `extension` 字段分辨）。

扩展被删或改名：节点**保留全部连线、标红**，提示找不到扩展。不自动删节点、不静默清空 —— 连线是用户的劳动，静默清掉比报错贵得多，而修法只是把目录拷回来。

## Considered Options

- **快照**（新建时把命令文本拷进节点）：存档更简单，跟现在完全一样，也不存在坏引用。但这跟「节点只是入口、被引用的是扩展」这个想法冲突 —— 而 `args` / `entry` 这类模板改动本来就该一次生效（改脚本内部的行为，快照也一样立刻生效，所以快照只省下了「模板改一次全画布跟随」这一件事，代价是多一个「从模板更新」的动作要维护）。
- **节点上存整行命令**（`run: node run.mjs --repo {{仓库}}`）：扩展能表达任意调用方式（`python`、`npx tsx`）。代价是每个扩展都在重复回答「怎么起自己」，而画布明明知道脚本文件在哪、该用哪个解释器；而且用户就被推回了「要写命令行」的那一侧 —— 这正是要消掉的东西。
- **引用里带版本**：扩展跟着画布走（[ADR-0012](./0012-extensions-live-in-the-workspace.md)），画布自带那一份，「哪个版本」没有第二个答案。版本字段只会多一个要同步的东西。
- **引用的身份做成 GUID**：要一张注册表来解析，改名即断，还得管「注册表丢了怎么办」。路径即身份：改名了就是找不到，报错比静默好。
- **走新节点种类**（像提取节点那样，[ADR-0007](./0007-extract-node-for-picking-a-value.md)）：提取节点的新种类是有理由的 —— 它不 spawn 进程、显示的也不是一份命令。扩展节点跑的还是命令、显示的也还是命令的输出，只有「命令从哪来」变了，够不上新种类。

## Consequences

1. 扩展节点在存档里**没有可编辑的 `command`**；`result.command` 仍然记下这次实际跑的那一条，所以节点上能回看「刚才到底跑了什么」。
2. 改扩展对**所有**引用它的节点立刻生效，不需要「从模板更新」这个功能。
3. 画布上要看得见两件事：这个节点引用的是哪个扩展，以及它要求的输入还有哪根边没连（缺边由既有机制报错，但缺在哪得看得见）。
4. 坏引用是一个必须显示出来的状态：标红 + 提示路径，连线与位置一律留着。
