# 进化面板：自动触发、记录、撤销

Status: proposed

ADR-0022 只做了「立即进化」和进化提示词。[ai-evolution.md](../ai-evolution.md)「用户怎么用」里还差开关、触发条件、进化记录和撤销。

决定：

- **面板**：工具条上的「立即进化」换成「进化」，点开右边一个窗口，就是 ADR-0022 的进化窗口加上面几样：
  开关、触发条件、进化提示词、「立即进化」、记录列表。进化时窗口照旧滚动显示过程。
- **配置跟工作文件夹走，但不在 pi 能改的三层里**：写在 `.mican/evolve/config.json`：

  ```json
  {"auto":true,"runs":50,"streak":5,"daily":"03:00"}
  ```

  `runs`：上次进化之后又攒够多少次运行；`streak`：某个节点连败多少次；`daily`：每天几点。
  哪项不填就不看哪项，任一项满足就触发。放 `mican.json` 会让 pi 能把自己的触发条件改掉。
- **什么时候看条件**：运行器每往 `runs.jsonl` 追加一行看一次 `runs` 和 `streak`；`daily` 由调度器排一个时刻。
  「上次进化之后」以最近一条进化记录的时刻为界（不管成没成、有没有改），所以一次没修好的连败不会马上再触发一次。
- **自动触发不打断在跑的链**：条件满足时有链在跑，就等所有链跑完再进化；手动触发照 ADR-0022 先停链。
  自动触发不带提示词，只照诊断改。
- **进化记录**：每次进化做完往 `.mican/evolve/history.jsonl` 追加一行：

  ```json
  {"at":1730000000000,"by":"streak","hint":"","ok":true,"snapshot":"a1b2c3d","commit":"e4f5a6b","message":"已进化 e4f5a6b：……","log":"1730000000000.log"}
  ```

  `by`：`manual` / `runs` / `streak` / `daily` / `undo`。没改、没过校验、出错的也记（没有 `commit`）。
  面板列出来，点开一条看 commit 说明、`git show --stat` 的改动文件和那次的过程 `.log`。
- **撤销**：记录上带 `commit` 的那一条可以点「撤销」，只退那一次，之后的改动留着。
  点的时候可以附一句撤销理由（如「这个脚本漏了附件」），空着也行；理由写进撤销那一行的 `hint` 和 revert commit 的说明里。
  1. 先停链、拍一份快照（跟进化一样，把用户没 commit 的改动先收进去，工作区干净了 `git revert` 才能做）。
  2. `git revert --no-commit <commit>`，然后跑 ADR-0022 那份校验。
  3. 没冲突、校验也过了：commit「撤销进化 <commit>」，有上游就 push，记一行 `by: "undo"`（带这次的 `snapshot` 和 `commit`，所以撤销本身也能再撤）。
  4. 有冲突或校验没过：`git revert --abort` 或回滚到第 1 步的快照，面板上说「后面的改动依赖这一次，单独撤不了」，
     并给一个「还原到这次之前」：三层和布局文件（ADR-0023）按那次的 `snapshot` 整份还原、另起一个 commit；
     点之前列出会一起丢掉的那几次进化，确认一次。

  不交给 pi 解冲突：撤销不该再依赖 AI。撤销和进化一样走只读，做完前端从盘上重开。
- **进化时把近期的 git 历史交给 pi**：提示词里加一段「最近的改动」，是三层和布局文件的最近 20 条 commit，
  每条只给说明和改动的文件（`git log -n 20 --stat -- <三层> <布局文件>`），不给 diff，要细看 pi 自己 `git show`。
  再加一句：被 revert 过的改法，除非这次有明确不同的理由，别再做。
  这样进化的说明、撤销和撤销理由、用户的手改都在一处，不另拼一份清单。
- **快照 commit 的说明改成「进化前快照（用户改动）」**：它收的是用户上次进化以来在画布上的改动，pi 看历史时要认得出来。
  没有改动就不产生 commit（ADR-0022 已经如此），不会刷屏。

## Considered Options

- **配置进 `mican.json` 的 `settings`**：跟画布走最自然，但 pi 能改它，要在校验里再加一条「不许动」。放 `.mican/`。
- **撤销只做整份还原到快照**：回到的是一个校验过的真实状态，不会冲突；但撤中间某一次会把之后的进化和手改一起丢掉。
  只留作 revert 撤不了时的退路。
- **revert 冲突了交给 pi 解**：等于又进化一次，撤销的结果变得不可预期。
- **从进化记录里挑出「被撤销的改动」单列给 pi**：要另维护一份清单，还看不见用户的手改。直接给 git 历史。
- **条件满足就停掉在跑的链去进化**：定时跑的链会被半路打断，重跑的代价可能比晚一会儿进化大。

## Consequences

1. 自动进化会在用户不在时改画布和扩展，全靠 ADR-0022 的校验和这里的撤销兜底。
2. 删掉 `.mican/` 就丢了记录和配置，git 里的 commit 还在，只是面板上看不到。
3. 撤销只圈三层和布局文件，`.mican/` 里的运行历史不回退；诊断靠进化记录的时刻分前后（ADR-0025）。
