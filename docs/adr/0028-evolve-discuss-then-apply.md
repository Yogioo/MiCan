# 进化先商量，点头再应用

Status: accepted（方案已定，还没实现）

[ADR-0022](./0022-evolve-now.md) 的「立即进化」是一次跑完：停链 → 快照 → 诊断 → pi 一次 → 校验 → commit。
[ADR-0024](./0024-evolve-panel.md) 又给它加了自动触发的条件。麻烦是之后才显出来的：
**改的往往是同一件事上的一点点** —— 「这行取法放宽一点」「提示词别漏掉附件」——
也要把整条流程重跑一遍：再等一次诊断、再等一次 pi 从头想、再等一次校验，中途还停工停链。
pi 那一轮只听得进一次话，说完就散（`--留会话 false`），下一轮什么也不记得。

拆成两段：**商量**（多轮对话，pi 改盘但不提交）和 **应用**（校验 + commit + push）。

## 两段

```
商量：诊断 ──> pi 第 1 版改动 ──> 你说一句话 ──> pi 只改这一点 ──> ……（同一份 pi 会话，改多少轮都行）
                                              │
应用：校验（结构 + 新扩展试跑）──> 过 ─> commit(+push)，记一条
                              └─ 不过 ─> 原因回到商量里，pi 接着改（最多 3 次）
放弃：三层还原到本次进化的快照
```

- **「方案」就是盘上那份还没提交的改动。** 面板列出改了哪几个文件、每份的 diff；画布照 ADR-0022 跟着盘上实时刷新，
  改过的节点描紫边。人审的是真实改动，不是一段「我打算这么改」。
- **点头 = 应用**：跑校验，过了就 commit，有上游就 push。**不点头 = 接着说**，或者**放弃**。
- **一次商量一份 pi 会话**：钥匙由进化后端取（如 `evolve-<时刻>`），交给
  [EXTENSION.md](../builtin/extensions/pi/EXTENSION.md) 里那把「稳定的钥匙」（没有就建、有就续）。
  第二轮起，诊断、你上面说过的话、pi 自己上一版怎么改的都在它上下文里，微调只改你指的那一处。
  每一轮仍是全新的 `pi` 进程，只是续同一份会话。

## 为什么是「先做出来」而不是「先写方案」

「先出方案、点头再改」有两种读法，这里取**先做出来、别提交**：

| | 要几次 AI 时间 | 「说的」和「做的」 |
| --- | --- | --- |
| 先写一段文本方案，点头后再让 pi 动手 | 两次（想一遍、再做一遍） | 可能对不上，要人对照 |
| 先做出来、不提交，diff 就是方案 | 一次 | 同一个东西，「对不上」不成立 |

主诉是慢 —— 微调还走全链路最慢。多一次「只想不做」的 AI 时间不但没省，比现在更慢。
盘上没提交的改动**不算生效**：不进 git、不推进 ADR-0025 的「上次改动之后」分界、不会被下一次自动进化当成既成事实；
点「放弃」整份还原。要它生效只有「应用」一个出口。

## 每轮各做什么

| | 第 1 轮 | 第 2 轮起 |
| --- | --- | --- |
| 诊断（含 ADR-0025 的 `since` / `worse`） | 给 | 不给（已在上文里）；点「重看诊断」才重算 |
| 三层 + 最近的 git commit（ADR-0024） | 给 | 不给 |
| 用户的话 | 进化提示词（可空） | 这一轮输入框里的话 |
| 结构校验（解析 `mican.json`、`docs/` 路径、`entry` 在不在） | 跑，结果当反馈 | 同左 |
| 新扩展试跑、commit | 不跑 | 不跑（留到应用） |

结构校验便宜，每轮跑一遍能让 pi 当场知道「这么改结构就不合法」；要起进程的「新扩展试跑」贵，放到应用那一下。
契约里加一句：**改完停手，不要自己 commit、不要自己 push** —— 那是进化后端的事。

## 触发器分两条路

- **手动**（面板上点）：走商量 —— 有人在场，就得等点头。
- **自动**（`runs` / `streak` / `daily`，ADR-0024）：照旧一次跑完，不等人。它不产生「没应用的版本」，所以没有等人点头这回事；
  唯一要顾的是别撞上一条开着的商量（见下节）。

## 记录、撤销、只读

- **只有应用那一下记一条** `evolve/history.jsonl`（`by: "manual"`，`message` 照旧）。商量期间的中间版本不记：
  明确不要每轮撤销；ADR-0025 的分界认的是带 `commit` 的记录，不受影响。
- **整段商量一个 commit**：应用后撤销就撤这一整段，ADR-0024 那套 revert 照旧。
- **商量期间一直只读，不是一轮的时长**（ADR-0022 那条只读，窗口拉长）：pi 在用文件工具改三层，不能跟人抢同一批文件。
  后端整个商量期间都算占着（`active` 为真），起新运行、定时器到点、前端落盘全挡着，直到「应用」或「放弃」；
  链要跑就先应用或放弃。代价见 Consequences 第 4 条。

## 关掉再打开：那版留着，对话也得接得上

- **不自动还原。** 商量没走到「应用」就关窗口、崩了、关掉应用，盘上那版改动留着 —— 脏得很合理，它就是「一版没应用的改动」。
  要它消失只有点「放弃」，要它生效只有点「应用」。
- **对话要复原。** 每轮结束往 `.mican/evolve/<at>/turns.jsonl` 追一行（`{at, role, text, ok}`）；面板打开时读回来，
  消息列表接着显示，输入框接着能发。pi 那头的钥匙还是 `evolve-<at>`，它自己把会话存在会话目录里 —— 两边都在，就是原来那条对话。
- **接不上也照样能聊。** `.mican/` 是能整个忽略、整个删掉的缓存目录（ADR-0026）：换台机器、或者清过缓存，
  往往只剩盘上那份改动，没有对话记录，pi 的会话也不在。这时新开一条对话，但不装作工作文件夹是干净的：
  第一轮就告诉 pi「三层里已有一版没应用的改动，是上次商量留下的」，让它先 `git diff` 看清它，在它上面接着改，别推倒重来。
- **认得出「有一版没应用」**：顶层 `evolve/pending.json` 记 `{"at":…,"snapshot":"a1b2c3d","session":"evolve-…"}`。
  面板打开先看它：在就顶上写一行「有一版没应用的改动」，配改动清单和「应用」「放弃」。
  它跟 ADR-0026 的 `evolve/` 一样不在 pi 能改的三层里；`turns.jsonl` 在缓存目录里，删掉只丢对话、不丢那版改动。
- **重启回来后照样占着**：`pending.json` 在就是「还在商量」，后端照商量期办（只读、起不了新链），直到应用或放弃——
  不然关掉再打开，链会踩到那版半成品上。
- **清单和「放弃」都按快照算，不按 HEAD**：`git diff <snapshot>`，`放弃` 也是还原到那个 `snapshot`。
  这样中间有谁 commit 过，认的仍是这次商量开始时那一版。`pending.json` 不在、盘上却是脏的，就说
  「认不出这一版是谁改的」，让人自己用 git 处理，不猜。
- **有商量没应用时，自动触发不进来**：条件满足也等应用或放弃之后再说（ADR-0024 那套条件照旧，只是先让路）。

## Considered Options

- **先写文本方案，点头后再让 pi 改**：多一次 AI 时间，正是要省的东西；还生出「说的和做的对不上」。
- **每轮 commit 一版**：不要；历史碎成一串半成品，撤销也不知道撤哪条。
- **每轮重跑诊断和全量校验**：诊断在同一个会话里本来就还在；全量校验要起进程，每轮都跑等于把慢的那个留住了。
- **商量搬进副本工作区（git worktree），线上全程不动**：线上一直干净、链照跑，是最干净的一头；
  但要加一层「改完怎么同步回线上」，以及「商量时人也在改线上」的合并说法。先不做，真被只读憋到再说。
- **自动进化也停在商量里等人**：用户不在时工作区一直脏，下一次触发看到半成品。否掉。
- **关掉窗口就当放弃**：安全，但那版改动连整段对话一起没了，商量很长时手滑关掉就白聊。
- **商量期间让链照跑，只挡住前端落盘**：链会半路读到 pi 正改着的扩展脚本。只读这一条本来就是为了不跟人抢同一批文件，
  放宽它省下的只是「等」，换出去的是「跑出来的东西是谁的半成品」。先不放宽。

## Consequences

1. `server/evolve.mjs`：`--留会话 false` 换成 `--会话 evolve-<at>`；`promptOf` 分出「第 1 轮」（带诊断和历史）与「后续轮」（只带这一句）；
   校验拆成「结构校验」与「全量校验」；`start` 之后多一组 `say` / `apply` / `discard` 和「正在商量」这个状态。
2. `/api/evolve` 的语义变了：不再一次请求跑完整条；多出 `/api/evolve/say`、`/api/evolve/apply`、`/api/evolve/discard`。
   轮次日志仍写 `.mican/evolve/<at>.log`，每轮一份提示词 `<at>-prompt-<N>.md`（今天已是这个形状）。
3. `src/ui/evolve-window.mjs`：下半部分从「提示词 + 立即进化」变成消息列表 + 输入框 + 改动清单 + 「应用」「放弃」；记录列表不动。
4. 只读窗口从「一次跑完」变成「聊完为止」，而且商量期间一直占着（不是一轮的时长）——自动进化不受影响，手动进化期间链和画布停得更久。这是这条路要付的代价。
5. 多两份文件：`.mican/evolve/<at>/turns.jsonl`（对话，删了就接不上旧对话、只能按盘上那版重开）和
   顶层 `evolve/pending.json`（「有一版没应用」这个事实、它的快照 sha 和会话钥匙）。
6. 第一轮多一个分岔：盘上已有没应用的改动就带一段「先看清它、别推倒重来」的提示词，盘上干净就是普通的第一轮。
7. `CONTEXT.md` 要不要加「商量」「应用」两个词；`docs/ai-evolution.md` 的「用户怎么用」要跟着改。
8. ADR-0022 的「立即进化」按钮被本单换成「开始商量」，那份 Status 要加一句注记；ADR-0024 的开关、条件、记录、撤销都不动。
