# 允许执行边分叉与成环，条件挂在边上

Status: 部分已实现 —— 分叉、成环、按值选路、兜底边、步数上限、命令行与超时已落地；搬进后端与定时触发未实现

ADR-0004 为了「一次跑完整条链」把执行图定成互不相交的直线：执行边两头都是单连接，没有分叉、没有汇合、也没有环。但真实流程是环形的 —— 「取工单 → 干活 → 验收 → 不通过就修 → 回到验收」，而且验收的结论还可能不止两种（通过 / 不通过 / 需澄清）。

决定：执行边可以带标签，标签就是**期望匹配的值**。一个节点跑完，拿它的值跟各条执行出边比对 —— 先找标签相等的，再找空标签的兜底边，都没有就停在那儿。于是出边不限根数、入边也不再设限、空标签是兜底、执行图允许成环，运行器就是**走路**，不是拓扑排序。

比对的那个「值」不是新概念：命令节点的值本来就是它的缓存文件（最近一次运行的输出），数据边送它，执行边挑它。

## 没有推翻什么

不引入 UE 的 Branch / ForLoop / Sequence 节点族。那族节点存在是因为 UE 的执行拓扑不能分叉；我们把分叉表达成同一节点上的多根出边、把条件挂在边上，所以用不着它们。ADR-0004 关于**数据边**的部分（`{{名字}}` 取正文、`[[名字]]` 取那份文件的绝对路径、命令节点的值就是缓存文件）一字未改，双流分离也照旧。

## Considered Options

- **判定节点 / JSON 分支节点**（把「从输出里取出一个字符串」做成一种节点）：这里否掉的是「把提取和分叉绑在一个新节点上」——分叉本来就是边的能力（后来改成了另做一种只管提取的节点，见 [ADR-0007](./0007-extract-node-for-picking-a-value.md)）。当时一并否掉的另两条是：内置 JSON 解析（agent 在非交互模式下控制不了自己的 stdout，输出只能当纯文本看）和 token 形式的 `{{名字.字段}}`。
- **「结论」独立于「值」**（取输出的最后一行，或在节点上另配一条「取结论」命令）：多一个几乎同义的词和一条魔法约定，而值已经在手上。
- **循环节点**（把环体装进一个新节点）：引入嵌套，会让「顺序」有两个表达方式。而环自己就圈定了范围 —— 环外的节点天然只跑一次。
- **重复做成入口的属性**（`×N` / `直到…`，图上仍是直线）：只能重复整条链，而例子里的环体只是链中一段。

## Consequences

1. **「运行链路」不再是直线**。`CONTEXT.md` 里的定义已改；`chain.mjs` 里那个顺着单根执行边走的 `walkDown` 作废。
2. **反环检查删掉，护栏换成步数上限**。`graph.mjs` 里 `reaches` 那道「这么连会成一个环」的判断取消；「跑飞了」的兜底变成单次运行的最大步数。它是**存档配置**（跟这份画布走，见 ADR-0008），不是机器级常量。退出码非 0 仍然只表示技术失败，停并报错，与选路无关。
3. **跑链搬进后端**。`runChain` 现在在前端 `src/ui/main.mjs`。定时触发（ADR-0005）和「网页不开也跑」都要求后端自己走图，所以「运行链路」和「运行命令」一起搬进后端，前端只发起和订阅事件流（后端给每次运行一个 id）。后端因此要读画布（`mican.json`）、按数据边的变量规则拼命令 —— ADR-0005 预告过这件事；好在 `graph` / `chain` / `vars` / `paths` 都是纯 ESM。
4. **命令行与超时跟着可配，都收进设置窗口**。原来 `cmd.exe` / `/bin/sh` 是硬编码的，而 `EXEC_TIMEOUT_MS` 是 2 分钟常量 —— 干活的 agent 会被它杀掉，现在默认 2 小时（上限 24 小时）。两个都只做**全局**（存在用户目录、不进存档）：超时是机器属性；命令行同理，节点级覆盖等真有人需要再加。顺手修了 spawn 那个引号 bug：命令整串裹双引号 + `windowsVerbatimArguments`，不这么干命令里的双引号会原样漏给被调程序（`findstr /c:"yes"` 会去找字面量 `"yes"`）。

5. **执行输入也不再限根数**。环的入口节点必然要收两根入边（外面一根、回边一根），只放开环、不放开入边，环还是画不出来 —— 这是实现到一半才撞到的。走路模型里它不引入歧义：光标只有一个，从哪儿来是确定的。ADR-0004 的「两头都是单连接」至此只剩出边那一半还能认（出边不限根数，但兜底边只能有一根）。

## 实现前还要定的语义

- **跑链期间前端和后端同时持有画布状态**：后端会写下游文本节点的 md 与缓存文件，前端内存里还是旧的，前端下一次自动落盘会把旧内容写回去（ADR-0002 说冲突时内存赢，但这里根本不存在「冲突」的判定）。可选：跑链期间前端只读，或者前端收到事件后重新拉一次状态。
