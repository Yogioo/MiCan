# 写一个扩展

一个**扩展**是工作文件夹里的一个目录，里面有一份 `EXTENSION.md`（声明）和它自己的实现。
画布扫到这个目录，就在右键菜单里生成一项；拖出来的节点引用它，运行时由画布把它拼成命令跑起来。

一个目录 = 一个动作 = 菜单里一项。想暴露八个能力就写八个目录。含 `EXTENSION.md` 的目录是叶子，不再往下扫；不含的目录只是菜单里的分组，继续往下。

这份文件跟扩展住在一起。现成样本从**设置 → 跟这份画布走 → 扩展**里「导入内置插件…」拷进来，照着改。

## 一个完整的例子

```
extensions/git-status/
├── EXTENSION.md
└── run.mjs
```

`EXTENSION.md`：

```markdown
---
name: git 状态
description: 把运行目录的 git 状态变成一段 JSON
entry: run.mjs
---

跑在节点的运行目录里，不需要参数。输出：

{"ok":true,"branch":"main","dirty":false,"files":[]}
```

`run.mjs`：

```js
import { execFileSync } from 'node:child_process'

const out = (args) => execFileSync('git', args, { encoding: 'utf8' }).trim()
try {
  console.log(JSON.stringify({
    ok: true,
    branch: out(['rev-parse', '--abbrev-ref', 'HEAD']),
    dirty: out(['status', '--porcelain']) !== '',
  }))
} catch (error) {
  console.log(JSON.stringify({ ok: false, reason: error.message }))
}
```

## `EXTENSION.md` 就这些字段

```yaml
name: git 状态          # 菜单里显示的名字
description: 把运行目录的 git 状态变成一段 JSON
entry: run.mjs          # 相对扩展目录的入口文件
args: --repo {{仓库}}   # 可选。{{名字}} 的值从数据入边的标签来
defaults:               # 可选。哪个输入留空又没连线，就拿它顶上
  仓库: my-repo
outputs:                # 可选。右边那些出口：名字 → 取法
  ok: json:ok
  text: json:text
route: ok               # 可选。用哪个出口当执行边的选路值（须单行）
```

- 不写 `inputs`：输入名就活在 `args` 那行的 `{{}}` 里。缺值时报「`{{仓库}}` 既没有入边也没有填值」—— 你不需要另外声明一遍。
- `defaults` 是**留空时的回退值**：端口旁边的框空着、又没有数据入边，才用它。
  所以拖出来的节点是干净的（框里只有一句灰色的提示），而改 `defaults` 对所有引用它的节点立刻生效（改 `args` 那行也一样）。
- `outputs` 是**声明的出口**，不是某次运行扫出来的键。右边一行一个；从它拉出的数据边只送这一份字段。
  取法跟提取节点同一套（`json:ok`）。对象/数组不当值。多行的字段走 `[[ ]]`，给的是挨着缓存文件的那份边车。
  取不到就停并报错，不静默给空。
- `route` 写出哪个出口当选路值。不写就仍比整份 `stdout.trim()`，旧扩展不用改。true/false 仍写在执行边上，不是节点上的出脚。
- 不写工作目录：那是**节点的**，不是扩展的。
- 不写解释器：`entry` 由 `node` 跑。
- **正文写给人看和给 AI 看的东西**：JSON 输出的形状、兜不住时吐什么、重入要求、依赖怎么装。

## 画布拼出来的命令

```
node "<工作文件夹绝对路径>/extensions/git-status/run.mjs" --repo <边上的值>
```

工作目录按节点的来（节点自己设的 > 画布的运行目录 > 工作文件夹），**不用 `--workspace` 这类参数把目录传进来**：`process.cwd()` 就是它。把 `git status` 封装成扩展，参数本来就是运行目录。

## 输入的两种形态

| 写法 | 拿到什么 | 用在哪 |
| --- | --- | --- |
| `{{名字}}` | 来路的**正文**，必须单行 | 短参数：工单号、仓库名、模型名 |
| `[[名字]]` | 来路那份文件的**本机绝对路径** | 整份 JSON、提示词 |

两者都从**数据入边的标签**取值（来路是文本节点就给那份 md，是命令节点就给它的缓存文件）。

也可以**不连边**：画布上每个命令节点会为它命令里的每个 `{{名字}}` / `[[名字]]` 在左边排一个端口，
端口旁边的框里直接填常量就行（短参数很适合这么干，不必为它专门摆一个文本节点）。
**同一个名字既连了边又填了值，以边为准** —— 那个框会让位，写上「由连线提供」。
端口本身也能拖：从端口拉到别的节点上，那根边的标签会自己填成这个输入名。

扩展的 `args` 里写了几个 token，拖出来的节点上就有几行 —— 在 `EXTENSION.md` 里把常量写死
（`args: {{工单网址}} 策划验收 张远瞻`）也是一种做法，改一行，所有引用它的节点跟着变。

**硬约束：写进命令行的值必须单行。** 提示词、验收标准这类多行长文本，放进**文本节点**，用 `[[提示词]]` 把它的文件路径传给脚本，脚本自己去读 —— 顺便，这样提示词就是画布上一个能看能改的方框。（拿到一个路径之后是读文件还是当正文本身，是脚本自己说了算。）

## 输出的契约

**两条流走两条路：stdout 是值，stderr 是诊断。**

- **stdout = 节点的值。** 约定：吐**一段 JSON**，并且永远让它是合法 JSON。
- **stderr = 给人看的诊断。** 它不参与取值：带着淡色铺在节点的正文上，跑完存成缓存文件旁边的
  `.log`（刷新页面也还在），但**缓存文件和下游拿到的都只有 stdout**。

为什么分开：跑 agent、跑构建这类活的脚本，过程本身就该看得见——现在在干什么、第几步、
调了哪个工具。写成 stdout 会把值弄脏（下游一提 JSON 就崩），藏在心里又是黑盒。
所以**进度与日志一律写 stderr**，值那一头永远干净。
导入进来的 pi 扩展就是这么干的：`pi --mode json`
的事件流全翻成人话写到 stderr，stdout 上只留最后那段 JSON。

- **分路**：清单写 `route: ok`，执行边标签写 `true` / `false`。也可以仍用提取节点取一个字段再分路。取不到、取出来是多行，画布会**停下并报错**，不静默给空值。
- **整份 JSON 往下传**：不写出口名的数据边仍送整份 stdout；`[[结果]]` 拿到的就是缓存文件的绝对路径。某个出口走 `[[ ]]` 拿到的是那份边车。
- **兜底归你**：agent 会飘、命令会崩、网络会断。脚本要在外面兜一层，不合格就吐

  ```json
  {"ok": false, "reason": "一句话说明哪里不对"}
  ```

  于是链条能照常分路走「重试 / 退给人」，而不是停在半路。**稳定性不来自提示词写得好，来自脚本兜了一层。**
- **退出码**：非 0 会一并记在节点上（`failed`），但**分路只看值**，不看退出码。业务上的「没做成」应该是一份正常的 JSON，不是非 0 退出。

## 幂等与重入

链条可能在同一个工单上重跑：崩了的会被重新捡起来，验收不过的会带着问题再走一圈。
所以脚本要被跑第二次也不出事 —— 动手之前先看状态：分支在不在、评论发过没有、标签打过没有。**幂等是脚本的责任**，不是画布的。

## 依赖自负

`node_modules`、`package.json` 归扩展自己。MiCan 不装、不管、不解析，`entry` 写什么就跑什么。装依赖这件事你自己跑一次，或者写进扩展的正文提醒下一个人。

## 编排约定（写链的人看这一段）

这几条是约定，不是软件功能 —— 软件不会替你保证其中任何一条。

- **触发器只当闹钟。** 入口和定时器都**不传值**、没有缓存文件。轮询校验是链里的一个**普通命令节点**（跑脚本查有没有新工单），后面接提取节点、接分路：

  ```
  定时器 → 轮询校验 → 提取 → 分支
  ```

- **真相在工单系统身上，不在本地。** 链条接手一个工单时给它打一个标签（如 `mican-处理中`），做完换成终态或撤掉。这样「有没有新东西」自己就会变，比在本地记「上次看到什么」可靠 —— 本地那份换个机器、换份画布就没了。
- **一次一个。** 一条链处理一个工单。同一条链还在跑时这一圈跳过（画布本来就这么做），所以串行是天然的。
- **两类失败分开。** 业务失败（agent 说没做完、验收不过）是**正常的**，吐一个词沿执行边正常分路；环境失败（脚本崩了、超时、JSON 兜不住）是**异常**，链条停下、节点标红。
- **环境失败要在工单上留一条评论。** 无人值守的时候，工单系统是唯一会自动看到的地方 —— 停在画布上一整天等于没发生。
- **中断恢复靠时间戳。** 标签上留着开始时间；超过阈值（2 × 节点超时）还没动的，由**轮询脚本自己**当成待处理重新排。画布不提供「恢复」功能，也不落盘运行历史。
- **提交是显式的一步。** 别让 agent 在自己肚子里 commit：链条上放一个提交节点，才看得见、才能单独重跑。
