# 迭代这份工作文件夹

一次迭代做完 = 用户要的那一层已经改完，并且该层的「做完」成立。

## 三层

| 层 | 活文件 | 改什么 |
| --- | --- | --- |
| 画布 | `mican.json` | 节点、边、存档配置、面板声明 |
| 文本节点 | `docs/` 里那份 md | 提示词、工单正文、计划 |
| 扩展 | 该动作的 `EXTENSION.md` 和它的 entry | 进出契约与脚本 |

`mican.json` 只有逻辑：节点的 `id` / `name` / `kind` 和各自的字段，边写的是 `id`。节点靠 `name` 找；新节点给一个画布内唯一的 `name`。
文本节点的正文只在 `docs/` 那份 md。

位置和视图在 `mican.layout.json`，不用改：缺位置的节点打开时自动摆。
面板的值在 `board/<名字>.md`。进化的配置和记录在 `evolve/`，不用改。

`.mican/` 是缓存目录：缓存文件 `.mican/<节点id>.out`、运行结果 `.mican/results.json`、运行历史、进化过程，都由运行产生，不用改。
版本管理只推荐忽略它（新建工作文件夹时自带的 `.gitignore` 就是这一行）；其余都该进仓库。

命令的**运行目录**看存档配置，可以不是本文件夹。

## 步骤

1. **点名一层。** 改链、改提示、改动作，分别落到画布 / 文本节点 / 扩展。一层不够再用下一层。做完：能说出改的是哪一层、哪几个文件。

2. **读活文件。** 画布读 `mican.json`；文本节点读那份 md；扩展先读该动作的 `EXTENSION.md` 再读 entry。写扩展时契约在 `extensions/README.md`。做完：将要改的字段或段落已经在眼前。

3. **改这一层。** 图和存档配置改画布；提示词改文本节点；各家 CLI 的差别收进脚本。多行文本走文本节点和 `[[名字]]`。脚本 stdout 仍是一段 JSON。做完：diff 只含这一层需要的文件。

4. **做完。**
   - 画布：`mican.json` 能解析；每个文本节点的路径在 `docs/` 里还在；每个扩展引用对应目录里还有 `EXTENSION.md`。
   - 文本节点：下游取法（`json:…`）或提示词契约仍然对得上改完的正文。
   - 扩展：`EXTENSION.md` 的 `entry` 指向的文件还在；不合格输出仍被兜成一份失败 JSON。
   - 面板：改的是那个名字的 md，别的名字没动。
